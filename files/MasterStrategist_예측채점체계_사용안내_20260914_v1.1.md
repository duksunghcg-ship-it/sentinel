# 예측 채점 체계 — 설치와 매일 하실 일

**발행** 2026-09-14 · **상태** 확정(v1.1) · **대상** 저장소 소유자 본인
**전제** 컴퓨터에 별도 프로그램을 설치할 필요가 없으며, 웹 브라우저와 휴대전화만 있으면 됨

---

## 0. 매일 하실 일은 한 가지뿐임

- 아침에 브리핑이 오면 맨 아래 「[예측]」 세 줄을 복사해, 저장소에 만들어 둔 「예측 기록함」 글에 댓글로 붙이면 됨. 휴대전화에서 30초면 끝남.
- 나머지는 전부 자동임. 다음 날 새벽 5시 30분에 시스템이 종가를 가져와 채점하고 성적표를 갱신함. 코스피는 다음 날 새벽에 바로 채점되고, S&P500은 미국 장이 확실히 끝난 뒤인 이틀 뒤 새벽에 채점됨(새벽 5시 30분은 미국 겨울철에는 아직 장중이라 확정 종가만 쓰기 위해 하루 늦춤).
- 빠뜨린 날은 「미기록」으로 남고 추정으로 채우지 않음. 며칠치를 댓글 하나에 몰아서 붙여도 전부 읽으며, 붙인 날짜가 아니라 예측 안에 적힌 날짜 기준으로 채점됨. 같은 날짜를 두 번 붙이면 먼저 붙인 것만 인정됨.
- 브리핑이 예측을 냈는데 그날 실제로 휴장이었으면 시스템이 「휴장」으로 표시해 성적에서 자동으로 뺌.

---

## 1. 설치 — 한 번만 하면 되는 4단계

### 1단계. 파일 올리기

1. 웹 브라우저에서 저장소 첫 화면을 엶.
2. 파일 목록 위쪽의 **Add file** 단추를 누르고 **Upload files**를 고름.
3. 전달받은 폴더 안의 파일을 화면에 끌어다 놓음. 폴더 구조가 그대로 유지되어야 하므로, 개별 파일이 아니라 `engine` 폴더와 `forecast` 폴더를 통째로 끌어다 놓는 것이 안전함.
4. 화면 아래 **Commit changes** 단추를 누름.

올라가야 하는 파일은 다음 여섯 개임.

| 위치 | 파일 | 역할 |
|---|---|---|
| `engine/` | `forecast_ingest.py` | 댓글에서 예측을 읽어 표로 옮김 |
| `engine/` | `forecast_score.py` | 종가를 가져와 채점하고 성적표를 만듦 |
| `forecast/` | `predictions.csv` | 예측이 쌓이는 표(처음에는 제목 줄만 있음) |
| `forecast/` | `parse_errors.csv` | 형식이 어긋난 예측이 기록되는 표 |
| `forecast/` | `SCOREBOARD.md` | 성적표. 매일 자동으로 다시 쓰임 |
| `forecast/` | `RULES.md` | 성적을 읽는 규칙과 변경 동결 규칙 |

### 2단계. 자동 실행 파일 교체

1. 같은 화면에서 `.github` → `workflows` → `sentinel.yml` 순서로 들어감.
2. 오른쪽 위 연필 모양 단추를 누름.
3. 안의 내용을 전부 지우고, 전달받은 `sentinel.yml`의 내용을 붙여넣음.
4. **Commit changes**를 누름.

바뀐 부분은 두 군데임. 채점을 실행하는 단계가 하나 추가되었고, 저장 대상에 `forecast` 폴더가 포함되었음. 채점이 실패하더라도 기존 거품 감지 산출은 그대로 돌아가도록 분리해 두었음.

### 3단계. 「예측 기록함」 만들기

1. 저장소 위쪽 메뉴에서 **Issues**를 누르고 **New issue**를 누름.
2. 제목에 `예측 기록함`이라고 적고, 본문에는 「데일리 브리핑의 [예측] 블록을 댓글로 붙이는 곳」 정도로 적음.
3. **Create**를 누름.
4. 만들어진 글의 주소 맨 끝에 있는 숫자를 적어 둠. 예를 들어 주소가 `.../issues/7`이면 그 숫자는 7임.
5. 이 글은 닫지 않고 열어 둠. 휴대전화에서 바로 열 수 있도록 즐겨찾기에 넣어 두면 편함.

### 4단계. 글 번호 알려주기

1. 저장소 위쪽 메뉴에서 **Settings**를 누름.
2. 왼쪽 목록에서 **Secrets and variables** → **Actions**를 누름.
3. 가운데 탭 중 **Variables**를 고르고 **New repository variable**을 누름.
4. 이름 칸에 `FORECAST_ISSUE`, 값 칸에 3단계에서 적어 둔 숫자를 넣고 저장함.

이 단계를 건너뛰면 채점은 돌지만 예측이 수집되지 않아 성적표가 계속 「표본 0건」으로 남음.

### 설치 확인

- **Actions** 메뉴에서 `sentinel-daily`를 고르고 **Run workflow**를 눌러 즉시 한 번 실행함.
- 초록색 표시가 뜬 뒤 `forecast/SCOREBOARD.md`를 열어 첫 세 줄이 보이면 설치가 끝난 것임.

## 2. 매일 하는 동작

1. 아침 브리핑 맨 아래 「[예측]」으로 시작하는 세 줄을 복사함.
2. 「예측 기록함」 글을 열어 댓글 칸에 붙여넣고 등록함.
3. 끝. 다음 날 새벽에 채점됨.

붙여넣을 때 다른 말을 함께 적어도 무방함. 시스템은 「[예측]」으로 시작하는 부분만 읽음. 다만 세 줄의 형식 자체는 고치지 말 것. 형식이 어긋나면 채점되지 않고 오류 표에만 남음.

---

## 3. 성적을 보는 법

- `forecast/SCOREBOARD.md`를 열면 첫 세 줄에 표본 수, 기준선 대비 우위, 보정 상태가 나옴.
- **기준선 대비 우위 한 줄만 보면 됨.** 적중률이 높아 보여도 기준선이 함께 높으면 실력이 아님. 지수는 오르는 날이 내리는 날보다 많아서, 매일 상승만 찍어도 적중률이 절반을 넘기 때문임.
- 초기 몇십 건 구간의 큰 수치는 실력이 아니라 표본이 작다는 뜻임. 60영업일이 쌓이기 전에는 성적을 근거로 아무것도 바꾸지 않기로 규칙에 못 박아 두었음.
- 1년(250영업일)이 지난 시점에 우위가 3%포인트에 못 미치면 일간 방향 예측을 접고 브리핑을 사실 요약 위주로 되돌리는 것이 예정된 결론임.

## 4. 문제가 생겼을 때

| 증상 | 원인과 조치 |
|---|---|
| 성적표가 「표본 0건」에서 변하지 않음 | 4단계의 글 번호 등록을 빠뜨렸거나 번호가 틀렸음. Settings에서 값을 확인함 |
| 붙여넣은 예측이 표에 없음 | `forecast/parse_errors.csv`를 열면 사유가 적혀 있음. 대개 방향에 「보합」을 썼거나 확률을 숫자로 적지 않은 경우임 |
| 일부 날짜가 「미채점」으로 남음 | 종가를 가져오지 못했거나 아직 확정 종가가 나오지 않은 날임(S&P500은 원래 이틀 뒤 채점됨). 다음 실행에서 자동으로 다시 시도하므로 그대로 두면 됨 |
| 어떤 날짜가 「휴장」으로 표시됨 | 그날 해당 시장이 열리지 않았던 것임. 성적에서 자동으로 빠지며 조치할 것 없음 |
| 자동 실행이 빨간색으로 실패함 | 채점은 실패해도 거품 감지 산출을 막지 않도록 분리해 두었음. 판정 자체는 정상이므로 급히 손댈 필요 없음 |
